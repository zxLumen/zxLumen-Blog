# 抖音调研：app 能不能像视频一样被刷

2026-11-11 · 调研对象：抖音（内容分发机制 + 小游戏分发先例）· 落地对象：zxlumen 应用平台

## 0. 一句话结论

抖音的推荐算法你基本都具备（多目标 + 赛马 + 复访 + 探索），你真正缺的是它**前面那 3 秒**：卡片能不能让人 3 秒看懂、愿意点。
现在 10 张卡只有「图标 + 名字」，等于抖音的封面是一块纯色 + 标题只有一个词 —— 完播率必然崩，算法再好也没用。

## 1. 抖音靠什么分发（2025 官方口径）

2025-03-30 上线 `trust.douyin.com`，2025-04-15 开放日首次公开算法原理：

- 模型层：协同过滤、双塔召回、Wide&Deep。**几乎不依赖人工打标签**，用神经网络预估用户对每个内容的行为概率。
- 北极星：**用户长期价值**，不是单次点击。
- 多目标：完播、评论、点赞、对作者的长期消费、分享、跟拍……组合成价值分，取最高分推给用户。
- 三个组合目标值得抄：
  - **收藏 + 复访**（知识类内容能推给真有需求的人）
  - **关注 + 追更**
  - **打开 + 搜索**（从"被推荐"变成"主动来找"）
- 专门设**探索指标**（主动推没消费过的品类，破信息茧房）+ **原创性目标**。

业内口径（非官方，多篇一致，仅作参照）：新内容进基础流量池 500–5000 曝光，3 秒留存 ≥60%、完播率 ≥35% 才进 5 万 / 50 万级池。
关键判断：**完播率只是入场券，不是奖杯** —— 2025 年算法公开后权重已从"前三秒 + 封面 + 短"转向收藏/复访等长期行为。

## 2. 抖音自己已经把「应用当视频」验证过了

这不是类比，是抖音已经跑通的产品：**抖音小游戏**。

- 规模：2025 年抖音小游戏市场份额接近 30%，入驻厂商同比 +100%、游戏数 +70%、活跃用户 +120%（2026 抖音小游戏行业白皮书 / 极光）；2026 上半年 DAU 同比 +130%（巨量引擎）。
- 核心动作是**「推荐流直出」**：小游戏在信息流里像视频、直播、电商一样被直接消费，不用跳转、不用下载。复访版接入周期 2–5 天。
- 留存命门是**侧边栏**：头部发行商 67% 回流来自侧边栏；官方口径"引入侧边栏后整体留存率 +18 个百分点"。
- 入口从"一个 App"变成"一组场景"：短视频、番茄小说、红果短剧等 7 个场景，跨场景用户占比 >20%。

也就是说：**抖音已经替你把"app 是信息流里的一张卡"这条路走过一遍，并且证明它在抖音的量级上成立。**

## 3. 三个前提，在你这里不成立（照抄会死）

| 维度 | 抖音 | 你 |
|---|---|---|
| 供给 | 每天千万条新内容 | 19 个线上 app，应用栏 10 张卡 |
| 消费成本 | ≈0（滑走 1 秒） | 1–3 分钟 + 学习成本 + 授权/登录 |
| 会话形态 | 一条连续会话，无限下滑 | 每次打开是一个目的地，用完就关 |

推论：**你的瓶颈不是排序，是「供给量 × 单卡转化率」。**
19 个 item 上推荐算法，等于 19 个人里选谁先上——没有意义。把 10 张卡的转化率从 5% 提到 15%，等于凭空多出一倍有效供给。

## 4. 可迁移的 5 条（按 ROI 排序）

### 4.1 卡片 = 视频的前 3 秒（最高 ROI）

抖音一条内容是「封面 + 一句话 + 3 秒内的确定收益」。
你现在 `apps/next-home/src/lib/app-config.ts` 的 `AppItem` 字段：`id / name / url / icon / openIn / group / bind` —— **没有 tagline、没有首屏截图、没有分类、没有"点进去 30 秒能得到什么"**。

要加 4 个字段：

| 字段 | 约束 | 例子 |
|---|---|---|
| `tagline` | ≤14 字，动词开头 | 「30 秒测出你的 MBTI」 |
| `hook` | 首屏 1 帧截图/动图，≤120KB | 对话界面截帧 |
| `tags` | 1–3 个 | 情绪 / 1 分钟 / 免登录 |
| `action` | 一个主按钮文案 | 开始 / 生成 / 测一测 |

验收：卡片高度 ≤ 屏高 1/3，3 秒读完知道按哪里。

### 4.2 冷启动池 + 赛马（照抄抖音，但把量级缩小 20 倍）

新 app / 新卡片进池固定给曝光：**每张 200 次**（抖音是 5000，你的量级不配）。
三个数分层：

- `s3` = 卡片曝光后 3 秒仍在页面的比例（前端可测，现在没有）
- `ctr` = `app_click / 曝光`
- `r7` = 7 天内同 `cid` 再次打开该 app / 打开过的 `cid`

规则（**阈值先行，不用模型**，符合你的偏好）：

- `ctr < 8%` 且 曝光 ≥200 → 下架回炉，重写 `tagline` / 换 `hook`
- `ctr ≥ 15%` 且 `r7 ≥ 20%` → 进常驻位
- 中间 → 留在池里轮换

抖音：完播只是入场券。你这里对应：**ctr 只是入场券，r7 决定它配不配占首页位置。**

### 4.3 复访入口（对应抖音的"侧边栏 67% 回流"）

你现在有 15+ 个公开子域 + SSO，但用户回来既没有理由、也没有入口。
低成本做法：主站固定「最近用过的 3 个」+ 每周一封"你上周用了 X、Y，本周 Z 更新了"（邮件通道 `mailer.py` 已有）。
成本远低于推荐算法，收益最直接。

### 4.4 探索位（防"3 个 app 吃掉 90% 曝光"）

抖音设专门探索维度。你这边：每次进流，**固定第 4 张卡 = 你 30 天没打开过的 app**，每会话 1 次。
否则 19 个 app 会迅速分化成 3 个活人 + 16 个僵尸。

### 4.5 创作者激励 → 你只有一个创作者，所以问题是"发布节奏"

抖音靠创作者生态供内容；你只能自己供。所以要定的是节奏：**19 个 app 里挑 3 个，每周各发 1 个"新片段"**（新功能 / 新数据 / 新玩法），其余只维护。
（与 360 行体验短视频线无关，那条已 parked，不碰。）

### 埋点现状（这是最便宜的一块）

`apps/next-home/data/zx.db` → `events` 表：

- 表结构**是对的**：`visit / leave / section_view / app_click / project_click / vlog_play`，带 `cid` 和 `dwell`，`/api/track` 已经在校验写入。
- 但 655 条记录里 **500 条 referrer 是 localhost**，最后一条 **2026-10-20 22:40** → **生产没在跑**。
- 64 个 cid / 21 天；`project_click` 共 47 次、`app_click` 15 次（且主要是自己点）。

直接后果：现在算不出 ctr / s3 / r7，**赛马没有数**。补埋点的成本是一天，收益是后面所有判断都有依据。

## 6. 应用流 v0（已按「主站二级页」方案落地）

落点：`/apps` 二级页，首页（个人主页 + 简历门面）完全不动，只在顶栏加了「应用」入口。

- 形态：竖向卡片流，一屏约 2.5 张（桌面 28dvh / 手机 34dvh 高），滚动吸附。
- 卡片：`tagline` + `hook` 首屏图（没图退回图标，不出现破图）+ 1 个主按钮 + 1–3 个 tag
  + 「昨天用过 / 3 天前用过 · 共 N 次」。
- 排序：`0.5×ctr + 0.3×r7 + 0.2×新鲜度`，曝光 <200 进冷启动池加 0.15；
  第 4 张固定插访客 30 天没打开过的一张（探索位，角标「换个口味」）。
- 数据：新增 `eventStore.appFunnel(days)` / `viewerAppHistory(cid, days)`，口径与
  `docs/STATS.md` 一致；页面 60 秒缓存，无数据时退化成 admin 配的顺序。
- **不做**：双塔召回、embedding、个性化模型。19 个 item 用 `ORDER BY` 就够，上模型是负债。
- 验收：埋点能出 ctr / s3 / r7；连续 7 天有数；至少 1 张卡 ctr ≥15%。

## 7. 明确不做

1. 不做视频号 / 内容平台 —— 那才是"视频平台"，和"应用平台"的定位相反。
2. 不做抖音账号矩阵铺量 —— 1 个人 0 剪辑产能，供给端撑不住。
3. 不给 19 个 app 全量做卡片 —— 先做 5 张，跑出 ctr 再铺。
